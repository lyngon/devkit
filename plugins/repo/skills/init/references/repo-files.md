# Repository files

Templates and rules for the files the skill writes.
Replace every `{placeholder}`.
Do not leave template comments in generated files.

## Division of labor

| File | Audience | Contains |
| --- | --- | --- |
| `INTENT.md` | Both | Why and for whom: product, audiences, done, failure, non-goals, horizon. Changes only when the purpose changes |
| `README.md` | Humans | How to use: getting started, layout, contributing, license |
| `CLAUDE.md` | Agents | How to work: checks and tests, layout, conventions, where docs go, do-not-touch list |
| `CONCEPTS.md` | Both | Terms only, no implementation |
| `docs/conventions/<topic>.md` | Agents and humans | Repository-specific conventions too long for a `CLAUDE.md` line. Never organization-wide conventions, which come from plugins. Created lazily |

Anything that fits two files goes in the one whose audience needs it first; the other links to it.
`README.md` and `CLAUDE.md` point to `INTENT.md` and `CONCEPTS.md` in their first lines rather than repeating them.
Stories, acceptance criteria and release plans do not belong in `INTENT.md`; they go to the issue tracker.
`CLAUDE.md` contains only repository-specific content: organization-wide conventions are distributed by another mechanism and must not be copied in.

`CLAUDE.md` is the source file. `AGENTS.md` is a symlink to it:

```sh
ln -sfn CLAUDE.md AGENTS.md
```

## INTENT.md

Written from the round 1 answers only.
Every section is required; keep the whole file under fifty lines.

```md
# Intent

What this repository is for, for whom, and what done means.
It changes when the purpose changes, not when the plan changes.

## Product

**{Product name}** {one or two sentences: what it is and the problem it solves}.

## For whom

- Repository: {who reads and changes the repository}.
- Artifacts: {who consumes what it produces}.

## Done means

- {Two to four observable outcomes that mean the repository succeeded.}

## Failure means

- {The failure-in-a-year answer, as two to four observable outcomes.}

## Non-goals

- {Each non-goal from the interview, one line.}

## Horizon

{Throwaway, months, or years}. {One sentence on why.}
```

## CLAUDE.md

````md
# {Repository name}

{One sentence: what the repository is and the problem it solves.}
Purpose, audiences, done and non-goals are in [INTENT.md](INTENT.md).
How to use and contribute is in [README.md](README.md).
Terms are in [CONCEPTS.md](CONCEPTS.md).
Decisions are in [docs/adr/](docs/adr/).

## Checks

Every tool comes from `devenv.nix`. If one is missing, add it there; never install anything imperatively.

```sh
devenv test
```

`devenv test` runs every git hook on every file, then `enterTest` from `devenv.nix`.
devenv detects coding agents and hides task output; run with `DEVENV_NO_AI_AGENT=1` to see it.
{Per-package test commands, one line each, e.g. `cd packages/api && uv run pytest`.}
Never disable a hook to make a check pass.

## Layout

- `packages/<name>/`: one directory per artifact, each with its own `devenv.nix` imported from the root `devenv.yaml`.
{One line per existing package: what it is.}
- `docs/adr/NNNN-slug.md`: decisions about the repository. Package-local decisions live in `packages/<name>/docs/adr/`.
- `docs/TODO.md`: deferred work the owner explicitly chose not to do yet.
- `docs/conventions/<topic>.md`: conventions specific to this repository that need more than a line. {Omit until the first one exists.}
- `tmp/`: agent scratch output, gitignored, may be deleted at any time.
- `sandbox/`: human experiments, gitignored, may live for weeks. Do not write there unless asked.

## Conventions

- Commit messages follow Conventional Commits, enforced by the `commitizen` hook.
- Markdown uses one sentence per line. Line length is not checked.
- Prose and commit messages use no em or en dashes and no curly quotes, enforced by the `prose-lint` hook.
- `.mcp.json` and `.pre-commit-config.yaml` are generated by devenv and gitignored. `.claude/settings.json` is committed and edited by hand.
- `CLAUDE.md` is the source file; `AGENTS.md` is a symlink to it. Edit this file.
- Secrets are declared in `secretspec.toml` and never written into code, config or commits. {Omit when no secrets.}
{Stack-specific conventions from the interview, e.g. "Python packages are managed with uv; never pip install."}

## Documents

INTENT.md is why and for whom, README.md is how to use, CLAUDE.md is how to work, CONCEPTS.md is terms only.
A convention specific to this repository that needs more than a line goes in `docs/conventions/<topic>.md`, with a one-line pointer here.
Anything that fits two files goes in the one whose audience needs it first, and the other links to it.
Record a decision as an ADR only when it is hard to reverse, surprising without context, and the result of a real trade-off.
````

````md
## Getting started

Every tool comes from the devenv shell.

```sh
devenv allow
devenv shell
```

Automatic activation: either `direnv allow` (uses `.envrc`), or add `eval "$(devenv hook zsh)"` to your shell configuration and skip direnv.
The VS Code extension `mkhl.direnv` loads the same environment into the editor, which is what makes the tools available to the Claude Code extension.

Run every check the way CI does:

```sh
devenv test
```

{Per-artifact usage or delivery instructions, from the delivery question.}

## Contributing

{Branching and review expectations if stated; otherwise omit the section.}

## License

{SPDX name}. See [LICENSE](LICENSE).
````

Write a `LICENSE` file only when the interview settled a license.
Do not pick one on the user's behalf.

## .claude/settings.json

Committed, hand-maintained.
Registers the marketplace so colleagues get it without manual setup; enables only the plugins the user chose.
The key under `extraKnownMarketplaces` must equal the marketplace manifest name (`lyngon`): Claude Code registers under the manifest name and the `@marketplace` suffixes in `enabledPlugins` must match it. Project marketplaces are applied once per Claude Code process start, after the folder is trusted.

```json
{
  "extraKnownMarketplaces": {
    "lyngon": {
      "source": {
        "source": "github",
        "repo": "lyngon/devkit"
      }
    }
  },
  "enabledPlugins": {
    "repo@lyngon": true
  }
}
```

Private marketplace note for the README when the user is not the only contributor: colleagues need GitHub credentials that git can use (`gh auth login`, then `gh auth setup-git`) for the marketplace to install.

## CI

GitHub Actions default; mirror the same steps for another host.

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: cachix/install-nix-action@v31
      - uses: cachix/cachix-action@v16
        with:
          name: devenv
      - name: Install devenv
        run: nix profile add nixpkgs#devenv
      - name: Run git hooks and tests
        run: devenv test
```

Add delivery jobs (image build, package publish) only for artifacts whose delivery the user named, as separate jobs that depend on `test`.

## Package skeleton

For every artifact from the interview:

```text
packages/{name}/
  devenv.nix        languages and hooks for this package only
  README.md         one paragraph: what it is, how to run it
  docs/adr/         created lazily
```

Stack-specific files (`pyproject.toml`, `package.json`, `Cargo.toml`, `go.mod`, `main.tf`, `{name}.cabal`) are created with the stack's own initializer from inside the devenv shell (`uv init`, `pnpm init`, `cargo init`, `go mod init`, `cabal init`), not by hand.
